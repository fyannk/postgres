fyannk/postgres

PostgreSQL images without gosu

The official PostgreSQL image, rebuilt from upstream's own recipe with a single change: the step-down from root to postgres uses the distribution's setpriv instead of a bundled gosu binary. Every night, both images are scanned side by side with two scanners, and this page shows the result.

Why repackage

The official image ships gosu for one job: dropping from root to postgres once, at startup. gosu is a separate Go program, downloaded at build time and pinned to a release, and it carries the Go standard library it was compiled with. Every vulnerability later found in that toolchain is reported against every image that bundles it, and it stays there until gosu is rebuilt and upstream moves to the new release. Distribution updates cannot fix it.

setpriv does the same job and already comes with the distribution: on Debian it is part of util-linux, which every image contains anyway, and on Alpine it is a small package. It is patched through the normal package updates that the nightly rebuild picks up.

Nothing else changes. The Dockerfile, entrypoint, environment variables, init scripts and tags are upstream's, so switching is a matter of changing the registry prefix: 

docker pull ghcr.io/fyannk/postgres:18

How this is measured

  • Same inventory tool on both sides. Each image we publish carries an SPDX SBOM produced by Syft at build time. For upstream's image, Syft is run on the official image each night, pulled through mirror.gcr.io, Google's mirror of Docker Hub, which serves the same digests. Only linux/amd64 is compared, the platform published here.
  • Two scanners. grype scans those SBOMs, including the Go standard library compiled into any Go binary (grype's default skips that). Trivy scans the images themselves. They use different vulnerability databases and severity sources, so their counts differ; the gap between ours and upstream is what to compare.
  • "With a fix" means a fixed version of the affected package exists. Those are the findings a rebuild can clear. The rest are waiting on Debian, Alpine or upstream projects, for ours and upstream alike.
  • Same version, same base. Each row compares the same PostgreSQL release on the same Debian or Alpine release. The two images are built at different times, so distribution package versions can differ slightly between them.
  • Counts are one per advisory and package. Totals summed across images count an advisory once for each image it appears in.

The raw data is public: latest summary, history, and the SBOM of each published image, linked from its section above.
